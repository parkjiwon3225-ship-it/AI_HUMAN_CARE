# 08. 팀원과 공유·협의할 사항

> 이 문서는 **다른 파트(앱, 영상, 하드웨어)와 맞춰야 하는 것**을 모았습니다.
> 표의 `제안`은 음성 파트의 초안이며 **팀 합의로 바꿀 수 있습니다.** 합의된 내용은 이 문서에 날짜와 함께 기록합니다.

## 1. 지금 상태 (한 장 요약, 2026-11-03)

- 음성 파트는 **마이크 도착 전**입니다 (도착은 빨라도 11/14 이후).
- 공개 데이터로 학습한 모델이 라즈베리파이4에서 **판단 한 번에 약 14~21ms**로 돌아갑니다 (0.5초마다 판단해도 20배 이상 여유).
- 모델 점수는 좋지만 **연기·낭독 데이터 기준**이라 실제 환경 성능은 마이크 후에 알 수 있습니다 ([04](04_MODEL_EXPERIMENTS.md)).
- 마이크 없이 파일을 흘려 보내는 **가짜 실시간 감지기는 파이4에서 동작 확인**(판단 한 번 21.5ms). 아직 만들지 않은 것: 판단 규칙 정리, 클립 저장, 앱 전송 ([07](07_ROADMAP.md) A2~A6).
- **연속 환경에서는 창 단위 점수보다 훨씬 약하다**(아래 표). 모델 개선(v2) 진행 예정.

### 참고: 오경보 허용 수준을 정할 때 (현재 모델, 연속 환경 시험)
| 시간당 오경보 (소음만 / 말소리 있음) | 위급 문장 감지율 | 감지까지 걸린 시간(중앙값) |
|---|---|---|
| 18 / 40 | 약 49% | 약 1.7초 |
| 7 / 14 | 약 45% | 약 2.6초 |
| 0~1 / 2~5 | 약 25~30% | 약 2~3초 |

- 수치는 연기 데이터를 소음 위에 얹은 시험이라 실제와 다르고, v2에서 개선될 예정이다.
- 시간당 1회는 하루 24회다. **하루 몇 회까지 괜찮은지**를 팀이 정해야 규칙을 정할 수 있다.

## 2. 앱 쪽과 맞춰야 하는 것 (가장 급함: A5에 영향)

| # | 질문 | 선택지 | 제안 | 담당 | 필요 시점 |
|---|---|---|---|---|---|
| 1 | 파이가 앱 쪽으로 알림을 **어떤 방식**으로 보내는가 | 앱 서버로 HTTP 요청 / 푸시 알림 서비스 / 클라우드 저장소 + 알림 / 같은 네트워크 직접 전송 | 앱 서버(또는 클라우드)로 **HTTPS 요청**: 이벤트 JSON + 클립 파일 | 앱 파트 | A5 시작 전 |
| 2 | **클립 파일**은 어떻게 전달하나 | JSON에 포함 / 파일 업로드 후 주소만 전달 | 업로드 후 주소 전달 (20초 wav 약 640KB) | 앱 파트 | A5 시작 전 |
| 3 | 인증 방식 | 기기별 토큰 / 키 | 기기별 토큰 (저장소에 올리지 않음) | 앱 파트 | A5 |
| 4 | 전송 실패 시 | 재시도 횟수, 대기 간격, 보관 기간 | 지수 증가 간격으로 재시도, 로컬에 일정 기간 보관 | 음성+앱 | A6 |
| 5 | 앱이 보여 줄 내용 | 확률, 시각, 클립 재생, 확인/오탐 표시 | 시각, 클립 재생, **"실제 위급/오경보" 버튼**(모델 개선 데이터로 활용 가능) | 앱 파트 | A5 |
| 6 | **허용 오경보 수준** (하루 몇 회까지) | 정해야 기준값과 규칙을 조정 가능 | 팀 합의 필요 (예: 하루 몇 회 이하) | 팀 전체 | G3 이전 |
| 7 | 알림 **중복 정리** | 쉬는 시간, 같은 사건 묶기 | 감지 후 일정 시간 같은 사건으로 묶음 | 음성+앱 | A2 |

### 이벤트 JSON 초안 (제안)

```json
{
  "event_id": "evt_20261120_140321_001",
  "device_id": "<기기 이름>",
  "detected_at": "2026-11-20T14:03:21+09:00",
  "model": { "name": "urgent_v1", "threshold": 0.88, "consecutive": 3 },
  "score": { "max_prob": 0.97, "mean_prob": 0.93 },
  "clip": { "file": "evt_20261120_140321_001.wav", "sample_rate": 16000, "channels": 1,
            "pre_sec": 10, "post_sec": 10, "bytes": 640044 },
  "speaker": null
}
```

- `threshold`와 `consecutive`는 실제 마이크 데이터로 정한 뒤 채움 (지금 값은 예시).
- `speaker`는 화자 식별(확장 목표)을 만들면 채움. 지금은 `null`.
- 시각은 파이에 RTC가 없어서 **인터넷 동기화 후**의 값이어야 함 ([05](05_RASPBERRY_PI.md)).

## 3. 다른 파트와의 역할 경계

| 항목 | 현재 음성 파트의 입장 | 협의 필요 |
|---|---|---|
| **낙상 감지** | 현재 모델의 "낙상"은 쿵 소리가 아니라 **"넘어졌어요" 같은 말소리**를 잡는다. 쿵 하는 충격음 감지는 별도 모델/출력이 필요해서 보류 | 영상 파트의 낙상 감지와 어떻게 역할을 나눌지, 알림을 합칠지 |
| 최종 장비 | 개발은 라즈베리파이4, 최종은 파이5 (파이4에서 되면 더 빠름) | 같은 장비에 영상과 음성이 같이 올라가는지 (CPU 경쟁) |
| 설치 장소 | 마이크 위치와 TV·가전 위치에 따라 오경보가 달라짐 | 시연 장소, 와이파이 환경 |
| 알림 연동 | A5의 협의 결과에 따름 | 영상 알림과 한 화면에 보여 줄지 |

## 4. 개인정보와 녹음 (꼭 지킬 것)

- **다른 사람의 목소리를 녹음할 때는 사전에 동의서를 받는다.** (AI Hub 데이터 구축 문서도 녹음 대상자의 허가와 동의서를 요구하는 절차를 설명한다.)
- 감지 시 **집 안의 소리를 앱으로 보내는 기능**은 민감하다. 시연과 실사용에서 **누구의 동의로, 어디에 저장하고, 얼마나 보관하는지** 팀이 정해 두어야 한다 (제안: 전송은 암호화(HTTPS), 클립 보관 기간 제한, 오래된 클립 자동 삭제).
- **상시 녹음은 하지 않는다**: 파이는 최근 10초만 메모리에 들고 있고, 감지된 순간만 파일로 저장한다.
- 이 저장소에 **오디오, 모델 파일, 키, IP, 계정, 와이파이 이름을 올리지 않는다.**

## 6. 모델·데이터 공유 규칙

- **모델 파일(학습 결과)은 팀 안에서 공유 가능.** 단, 저장소에는 올리지 않고 팀 공유 폴더 등으로 전달 (`.gitignore`가 막고 있음).
- **AI Hub 데이터 원본은 재배포 금지.** 각자 AI Hub에서 신청해 받는다.
- 코랩 노트북과 스크립트는 [../code](../code)에 있고, 재현 순서는 [06](06_COLAB_RUNBOOK.md).
