## 2. AI Hub 088 데이터의 구조 (실측)

- 구성: Training / Validation × 라벨링데이터(JSON zip) / 원천데이터(wav zip). 클래스별로 zip 하나(큰 클래스는 분할).
- **JSON 1개 ↔ wav 1개**, wav 이름 = JSON 이름 + `_label.wav`.
- JSON 주요 필드: `audio.duration`(원본 길이), `annotations[0].area.start/end`(원본 안의 이벤트 구간), `audioType`(voice/sound), `note`(발화 문장 또는 소리 설명), `gender`, `generation`(child/teenager/adult/senior), `dialect`, `soundQuality`, `soundDistance`(근접/중간/원거리), `categories.category_03`(상황), `audio.acquisitionPlace`(실내/실외).
- **wav는 이미 `area` 구간만큼 잘려 있음** (wav 길이 ≈ `area` 길이). JSON의 `duration`은 원본 길이.
- **헤더의 샘플레이트·채널·비트가 파일마다 다름** (44.1/48/96kHz, 1·2채널, 16·32bit). JSON은 모두 "44.1Khz"로 적혀 있어 부정확.
- 모든 녹음이 같은 태블릿(갤럭시탭S6), `soundQuality`는 전부 "정상". 연기/제작 데이터.

- 노인(senior) 비율 (Training): 낙상 19%, 도움요청 14%, 응급의료 12%.

### 알려진 문제 (공통 대응은 [02_DECISIONS](02_DECISIONS.md))

| 문제 | 대응 |

## 3. 전처리 규칙 (`code/scripts/convert16k.py`)

1. 라벨 zip과 원천 zip을 이름으로 짝짓는다 (`wav 이름 = JSON 이름 + _label.wav`).
2. 필터: 위급은 `audioType == voice`이고 이벤트 길이 1.5~12초, 정상은 4~120초.
3. wav를 읽어 **헤더 기준**으로 모노(채널 평균) → **16kHz**로 변환.
4. wav 길이가 JSON `area` 길이와 ±15% 넘게 다르면 제외 (실제로 20클립).
5. **4초 창**: 위급은 4초보다 짧으면 반복해서 채우고(학습에서는 실제 구간만 사용), 긴 클립은 최대 2창. 정상은 클립당 무작위 최대 2창.
6. 선택: 위급은 문구(note)당 40클립 상한, 정상은 소음 종류별 돌아가며, **위급:정상 창 수 1:1**.
7. 저장: int16, 2,000창씩 `.npy` 샤드 + 메타 CSV (클래스, 문구, 성별, 연령, 장소, 거리, 원본 샘플레이트·채널, 클립 길이, 창 시작, 음량 rms dBFS).
8. 음량은 변환에서 건드리지 않고 메타에 기록. 정규화는 학습 단계에서.

### 변환 결과

| 세트 | 위급 창 | 정상 창 |
|---|---|---|
| Training | 10,664 | 10,682 |
| Validation | 4,277 | 4,282 |

- 합계 29,905창, 약 3.8GB, 변환 10분. 위급 중 4초 미만 클립(반복으로 채운 창) 48~50%.

## 4. 일상 말소리 (Zeroth-Korean) 처리 규칙

- 압축 파일(약 10.3GB)을 풀지 않고 스트리밍으로 읽어, 화자당 최대 60발화에서 4초 창(길면 2창)을 만든다.
- 결과: 학습 8,694창(105명), 시험 744창(10명), **시험 화자와 학습 화자 겹침 0명**.
- 학습에서는 70% 확률로 정상 소음을 SNR 0~25dB로 섞는다.
