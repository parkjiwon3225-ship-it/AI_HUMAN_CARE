# 09. 틀렸다가 바로잡은 것과 배운 점

> 과정에서 **처음 판단이 틀렸던 것**을 숨기지 않고 남깁니다. 같은 실수를 반복하지 않고, 이 문서를 읽는 사람이 어떤 점을 검산해야 하는지 알 수 있게 하기 위해서입니다.
> 이 프로젝트의 문서와 코드는 AI 어시스턴트(Claude)와 협업해서 작성했으며, 초기 설명 중 일부가 실측으로 정정되었습니다 ([CREDITS](CREDITS.md)).

## 정정 목록

|---|---|---|---|---|

## 방법에 관한 한계 (투명하게)

- AI가 작성한 코드는 **작성 환경에서 실행해 보지 못한 부분**이 있었다 (PyTorch 학습과 내보내기). 그래서 (a) 작은 데이터의 시험 실행(QUICK 모드), (b) 학습 환경과의 동일성 검산(특징 7.0e-06, 확률 2.1e-07), (c) 하위 그룹과 탐침 평가로 결과를 따로 확인했다.
- 속도 수치(예: 코랩 CPU 시간)에는 **추정**이 섞여 있으며 문서에서 `(추정)`으로 표시했다.

## 배운 점 (다음에도 지킬 것)

1. **문서나 메타데이터를 믿지 말고 실제 파일로 검산한다.** (샘플레이트, 길이, 구간 모두 문서와 달랐다.)
2. **점수가 쉽게 높으면 지름길을 의심한다.** 정상에 말소리가 없다는 사실 하나가 오경보 95%를 만들었다. 탐침(말소리, 합성음, 음량, 길이)과 홀드아웃으로 확인한다.
3. **기준값 0.5가 아니라 허용 오경보율에서 비교한다.** 에폭마다 오경보율이 0.7%~60%로 흔들려도 AUC는 안정적이었다.
4. **같은 출처의 검증 점수는 낙관적이다.** 마지막 판정은 실제 마이크로.
5. **측정하지 않은 것은 추정이라고 쓴다.** 숫자와 해석을 분리한다.
6. **작은 단계로 나누고 결과를 바로 저장한다.** 셀 분할, 실험별 결과 JSON, 이어받기.
7. **공개 저장소에 올리기 전에 개인 정보와 접속 정보를 지운다.**
