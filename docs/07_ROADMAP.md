## 마이크 오기 전 (11/02 ~ 11/13)

### A. 파이 소프트웨어 (마이크 불필요)
- [ ] A1. **가짜 실시간 감지기**: wav를 마이크처럼 잘게 흘려보내고 최근 2.5초를 0.5초마다 판단
- [ ] A2. **판단 규칙**: 기준값, 연속 N회, 소리 크기 게이트, 알림 후 쉬는 시간 (설정 파일로 조정)
- [ ] A3. **앞뒤 10초 저장**: 최근 10초 유지, 감지 시 이후 10초를 더 받아 20초 wav + JSON 저장
- [ ] A4. 저장 관리와 로그: 오래된 클립 삭제, 디스크 점검, 시각 동기화 확인
- [ ] A5. **앱 전달**: JSON 규격 확정, 노트북에 가짜 수신 서버를 두고 전송 시험 ([08](08_TEAM_SHARING.md) 협의 필요)
- [ ] A6. 부팅 시 자동 시작, 네트워크 끊김 재시도
- [ ] A7. 마이크 사전 준비: 드라이버 확인 명령, 녹음용 패키지 설치

### B. 모델 (코랩)
- [ ] B1. 약점 분석: 근접 녹음 찌그러짐 비율, "살려주세요" 낮은 재현율 원인, 공사장 오경보 샘플 청취 (CPU)
- [ ] B2. **스트리밍 평가**: 긴 연속 오디오(소음+낭독 사이에 위급 문장 삽입)로 시간당 오경보와 감지 지연 측정 (CPU)
- [ ] B3. **v2 학습**: 짧은 외침 보강, 큰 충격 소음을 정상으로, 낮은 재현율 문구에 가중 (GPU)
- [ ] B4. (선택) 사전학습 오디오 모델과 같은 시험으로 비교 (비명, 신음, 쿵 소리 가능성)
- [ ] B5. 최종 후보를 ONNX로 내보내 파이에서 속도 재측정

## 마이크 온 후 (11/14 ~)

### E. 설치와 점검 (1일)
- [ ] E1. HAT 장착, 설정 백업, 드라이버 설치, 재부팅 → `arecord -l`에서 카드 확인
- [ ] E2. 5초 시험 녹음을 노트북에서 청취 (작거나 찌그러지지 않는지)
- [ ] E3. 녹음 볼륨 조정, 16kHz 모노 변환 확인, 조용한 방의 잡음 수준 측정
- [ ] E4. A1 파이프라인의 입력만 마이크로 교체해 무음과 TV에서 확률 분포 확인

### F. 실제 데이터 수집 (며칠)
- [ ] F1. 정상 소리: 설치할 장소에서 TV, 라디오, 대화, 가전 (수 시간)
- [ ] F2. 위급 문구: 동의한 사람들이 거리·크기·배경(TV 켠 상태 포함)을 바꿔서. **낙상은 실제로 넘어지지 않고 목소리로만**
- [ ] F3. 평가용은 다른 날·다른 사람·다른 장소로 분리 (학습에 섞지 않음)

### G. 평가와 개선
- [ ] G1. **실제 녹음으로 현재 모델 평가**: 재현율, 시간당 오경보, 감지 지연 (가장 중요한 현실 점검)
- [ ] G2. 마이크 데이터를 섞어 재학습 (GPU 필요, 막히면 일회 구매 검토)
- [ ] G3. 기준값과 후처리를 목표 오경보(하루 몇 회 이하)에 맞춰 조정

### H. 통합과 안정성
- [ ] H1. 종단 시험: 위급 발화 → 감지 → 앞뒤 10초 저장 → 앱 알림, 걸린 시간 측정
- [ ] H2. 24시간 연속 운전 (온도, 메모리, 디스크, 와이파이 재접속, 시간 동기화)
- [ ] H3. 최종 장비(파이5)로 옮겨 같은 시험 반복
- [ ] H4. 최종 시연 시나리오, 결과표, 한계 문서화

### I. 시간이 남으면
화자 식별(등록된 사람 구분), 낙상 충격음(쿵 소리) 감지, 영상 팀 알림과의 통합.
