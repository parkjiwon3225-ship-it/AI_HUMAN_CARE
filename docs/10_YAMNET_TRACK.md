- **짝 규칙**: `10.낙상_{번호}_label.wav` ↔ `10.낙상_{번호}.json`. WAV가 없는 라벨은 응급의료 4개, 실내 192개 (Training).
- **위급 클래스는 사람 발화, 정상은 환경음**이라 "말소리 유무"가 지름길이 될 수 있다. YAMNet의 Speech 점수가 0.5를 넘은 클립 비율(클립 최대 점수, Training+Validation 표본): 낙상 0.99, 도움요청 0.95, 응급의료 0.92, **실내 0.42**, 실외 0.13. 실내는 배경 웅성임 때문에 말소리가 잡히므로 "정상에 말소리가 없다"는 것은 정확하지 않다.
- JSON의 `Mono` 표기는 믿을 수 없다. 실제 WAV는 1·2·3채널, 16·32bit가 섞여 있다 ([03](03_DATA.md)와 같은 결론).
- zip 안의 `_label.wav`는 이미 `area` 구간만큼 잘려 있다 (표본에서 WAV 길이 ≈ `area` 길이, 100%에 가까움).
- 클립 길이(Training 표본): 위급은 중앙 3.4~3.9초(최소 0.4초), 정상은 실내 중앙 54초, 실외 30초(최대 803초). **클립 길이 차이**가 평가를 낙관적으로 만들 수 있다 (§4).

## 3. 위상이 반대인 스테레오 (가장 중요한 발견)

일부 스테레오 WAV는 좌우 신호가 서로 반대(상관계수 < 0)다. 이런 파일을 채널 **평균**하면 소리가 상쇄되어 거의 무음이 된다.

| 구분 | 위상 반대 파일 수 |
|---|---|
| Training 표본 (v2, 총 16,000) | 낙상 398/6,000, 도움요청 10/3,000, 응급의료 18/3,000, 실내 79/2,000, 실외 42/2,000 |
| Validation (총 1,300) | **낙상 155/300**, 도움요청 1/300, 응급의료 2/300, 실내 13/200, 실외 3/200 |

처리 방식에 따른 결과 (Validation, 클립 평균 + 로지스틱 회귀, 같은 데이터 선정):

| 지표 | v1: 한쪽을 뒤집어 합침 | v2: 더 큰 채널 하나만 사용 |
|---|---|---|
| 낙상 Validation 맞힌 비율 | 0.543 | **0.980** |
| 그중 위상 반대 클립 (155개) | 0.135 | **0.974** |
| 말소리 점수 0.5 미만인 낙상 클립 | 161/300 | **12/300** |
| 위급 재현율 | 0.809 | 0.953 |
| 정상 정밀도 | 0.695 | 0.903 |
| 전체 정확도 | 0.862 | 0.962 |

- 해석(추정): 위상 반대 클립은 목소리와 효과음이 서로 다른 위상 성분에 있어서, 평균이든 차이든 한쪽 성분만 남는다. 한 채널은 둘 다 담고 있다. 합성 신호(목소리는 같은 위상, 효과음은 반대 위상)로 시험하면 더 큰 채널 하나가 두 성분을 모두 보존했다.
- 수치로 간접 확인했고, **직접 청취로는 아직 확인하지 않았다** (`probe_antiphase.py`로 만든 청취용 파일을 듣는 것은 `(확인 필요)`).
- 기존 갈래의 `convert16k.py`·`cell_05`는 채널 평균(`x.mean(axis=1)`)을 쓰므로 같은 영향이 있을 수 있다 `(확인 필요)`. [09 #13](09_CORRECTIONS_AND_LESSONS.md) 참고.

## 4. 분류기 결과 (모두 AI Hub Validation, 정상 소리 총 1.11시간)

- 판정 규칙: "N프레임 연속으로 확률이 임계값 이상이면 위급". 프레임 간격은 약 0.48초.
- **03**: 프레임 단위 MLP, 위급·정상 균형 가중치. **03b**: 정상 프레임 가중치 3배 + 위급 클립에서 말소리 점수 0.2 미만인 프레임은 학습 제외.

| 모델 | N | 임계값 | 위급 재현율 | 응급의료 재현율 | 정상 오경보(클립) | 시간당 오경보(약) |
|---|---|---|---|---|---|---|
| 03 | 1 | 0.5 | 1.000 | 1.000 | 0.290 | 104.4 |
| 03 | 2 | 0.9 | 0.969 | 0.917 | 0.030 | 10.8 |
| 03 | 2 | 0.95 | 0.962 | 0.897 | 0.020 | 7.2 |
| 03 | 3 | 0.95 | 0.752 | 0.530 | 0.010 | 3.6 |
| 03b | 1 | 0.5 | 0.960 | 0.923 | 0.060 | 21.6 |
| 03b | 2 | 0.5 | 0.911 | 0.867 | 0.018 | 6.3 |
| 03b | 2 | 0.9 | 0.868 | 0.793 | 0.005 | 1.8 |
| 03b | 3 | 0.8 | 0.603 | 0.443 | 0.002 | 0.9 |

- 03b는 재현율을 내리고 오경보를 줄인 **운영점 이동**에 가깝고 뚜렷한 개선은 아니다 (N=2에서 03 0.95가 0.962/7.2, 03b 0.5가 0.911/6.3).
- **측정 한계**: Validation 정상 소리가 1.11시간뿐이라 알림 1건이 시간당 약 0.9회다. 오경보 0건을 시간당 1회 이하로 확인하려면 정상 소리가 대략 3시간 이상 필요하다. 클립 평균 평가(§3 표)는 정상 클립(10초)이 위급 클립(약 3.5초)보다 길어 낙관적이다.
- 위급 재현율 90%와 시간당 오경보 1회 이하를 **동시에 만족하지는 못했다** (AI Hub 정상 소리 기준). 일상 대화·TV는 아직 평가하지 않았다.

## 6. 재현 순서 (`code/yamnet_track/`)

1. `scan_dataset.py`, `peek_zip.py`, `summarize_labels.py`: 폴더·zip·라벨 구조 확인 (zip을 풀지 않음)
2. `extract_subset.py`: 클래스별로 일부만 뽑아 16kHz 모노로 변환 (`--split`, `--per-class`, `--normal-per-class`, `--class-count`). 위상 반대 스테레오는 더 큰 채널 하나를 사용
3. `check_manifest.py`: 길이·음량·좌우 위상 점검, `probe_antiphase.py`: 위상 반대 클립을 L/R/평균/차이로 저장해 청취
4. `build_dataset.py`: 학습용 폴더 정리 (정상 클립은 10초로 자름). 2~4를 한 번에 하려면 `rebuild_v2.py`
5. 코랩: `01_extract_embeddings_v2.ipynb`(GPU 권장) → `02_error_analysis_v2.ipynb`(CPU) → `03_train_classifier.ipynb` → `03b_train_classifier.ipynb`(CPU)
